# UKSM 1.4 — регулятор напряжения с UART-клиентом

Проект встраиваемой системы управления выходным напряжением на **ATmega2560** и настольного приложения на **Python / Tkinter**. Микроконтроллер измеряет выходное напряжение через АЦП, формирует ШИМ для силового каскада, обрабатывает кнопки и команды UART. Приложение ПК позволяет устанавливать напряжение, переключать режимы работы, запускать калибровку и наблюдать телеметрию на графике.

## Возможности

- **WORK:** автоматическое регулирование измеренного напряжения ПИ-регулятором.
- **TEST:** ручное управление ШИМ, в том числе кнопками; автоматический ПИ-контур выключен.
- Измерение выходного напряжения на ADC0 и чтение потенциометра на ADC1.
- Установка уставки в диапазоне **30–250 В**; шаг изменения кнопками — **5 В**.
- Двусторонний обмен по UART с CRC-16, адресами устройств, номерами пакетов и ACK/NACK.
- Периодическая передача телеметрии (в текущем `main.c` — в ветке TEST), а также ответ на команду `GET_DATA`.
- Калибровка АЦП по одной точке и выходного напряжения по двум точкам.
- Сохранение параметров и калибровочных коэффициентов в EEPROM.
- График напряжения, журнал обмена и выбор COM-порта в клиенте.

## Оборудование и настройки прошивки

| Параметр | Значение в исходниках |
|---|---|
| МК | ATmega2560 |
| Тактирование | `F_CPU = 16 MHz` |
| UART | USART0, **9600 бод** по умолчанию |
| Адрес ПК (Master) | `0x02` |
| Адрес контроллера (Slave) | `0x01` |
| ШИМ | Timer1 / OC1A, **PB5** (Arduino Mega D11) |
| Частота ШИМ | 5 кГц (настройка `PWM_TOP = 399`, делитель 8) |
| ADC0 | Измерение выходного напряжения (Arduino Mega A0) |
| ADC1 | Потенциометр (Arduino Mega A1) |
| Кнопка UP | PD0 (Arduino Mega D21), с подтяжкой |
| Кнопка DOWN | PD1 (Arduino Mega D20), с подтяжкой |
| Встроенный LED | PB7 |
| Режим по умолчанию | TEST |
| Уставка по умолчанию | 30 В |

Параметры задаются главным образом в `config.h`, `input.h` и `pwm.h`. Номера Arduino приведены для платы Mega 2560, а сама прошивка написана на **AVR C**, не в формате Arduino Sketch.

### Периоды обработки

| Операция | Период в коде |
|---|---:|
| Измерение напряжения | 1 мс |
| Обработка кнопок | 5 мс |
| Пересчёт ПИ-регулятора в WORK | 5 мс |
| Передача периодической телеметрии в TEST | 100 мс |

Временные интервалы организованы через **Timer2** и опрос `get_time_ms()` в главном цикле. **FreeRTOS в данном проекте не используется.** Значения являются заданными периодами планирования, а не подтверждёнными измерениями реальной задержки.

### 3. Проверка связи

1. Подключите UART0 контроллера к ПК через подходящий **USB–UART адаптер с совместимыми логическими уровнями**; соедините TX с RX, RX с TX и общую землю **только если это допустимо по схеме изоляции и безопасности**. Не подключайте TTL-UART напрямую к RS-232.
2. Запустите клиент, выберите COM-порт и **9600 бод** (или одинаковое значение в прошивке и приложении).
3. Оставьте адреса по умолчанию: `Master ID = 0x02`, `Slave ID = 0x01`.
4. Нажмите **«Подключить»**, затем отправьте `GET_DATA`.
5. Проверьте журнал принятых пакетов и график напряжения.

```text
└─────────────────────────────┘                                  │ Основной цикл         │
                                                                 │  ├─ АЦП / кнопки      │
                                                                 │  ├─ ПИ-регулятор      │
                                                                 │  ├─ Timer1 → PWM      │

                                                                 └──────────────────────┘
```

Основной цикл выполняет опрос UART, кнопок и напряжения. В WORK рассчитывается новое воздействие ПИ-регулятора, а в TEST управление ШИМ производится вручную. Параметры режима, уставки, адресов и калибровки хранятся в EEPROM; чтение настроек сопровождается проверкой CRC.

## Протокол UART

Клиент и прошивка используют бинарные пакеты фиксированной длины. Контрольная сумма рассчитывается по байтам пакета **до двух байтов CRC**.

**CRC-16:** начальное значение `0xFFFF`, полином `0x8005`, побитовая обработка MSB-first; CRC передаётся старшим байтом вперёд. Это важно: результат не следует автоматически подменять стандартным `CRC-16/IBM` с отражением битов.

### Команда ПК → контроллер (9 байт)

| Смещение | Поле | Размер | Формат |
|---|---|---:|---|
| 0 | Start | 1 | `0x55` |
| 1 | Master ID | 1 | Адрес ПК |
| 2 | Slave ID | 1 | Адрес устройства |
| 3 | Packet number | 1 | Номер пакета |
| 4–5 | Value / Setpoint | 2 | `uint16`, big-endian |
| 6 | Command | 1 | Код команды |
| 7–8 | CRC-16 | 2 | Big-endian |

### Ответ контроллера → ПК (13 байт)

| Смещение | Поле | Размер | Формат |
|---|---|---:|---|
| 0 | Start | 1 | `0xAA` |
| 1 | Master ID | 1 | Адрес ПК |
| 2 | Slave ID | 1 | Адрес контроллера |
| 3 | Packet number | 1 | Номер исходящего пакета |
| 4–7 | Voltage | 4 | `float32`, little-endian |
| 8–9 | Setpoint | 2 | `uint16`, big-endian |
| 10 | Status | 1 | Статус, режим, ACK/NACK |
| 11–12 | CRC-16 | 2 | Big-endian |

В байте `Status` **бит 7** соответствует режиму (`0 = TEST`, `1 = WORK`), **бит 6** — типу ответа (`0 = ACK/телеметрия`, `1 = NACK`). Остальные биты используются для кодов ошибок; их трактовку следует сверять с `config.h` и кодом клиента.

### Команды

| Код | Назначение |
|---|---|
| `0x70` | Изменить уставку напряжения |
| `0x40` | Установить режим TEST/WORK (`Value = 0/1`) |
| `0x30` | Запросить текущие данные (`GET_DATA`) |
| `0x50` | Начать калибровку АЦП |
| `0x10` | Передать точку калибровки АЦП |
| `0x60` | Начать двухточечную калибровку выходного напряжения |
| `0x20` | Передать точку калибровки VOUT |
| `0xA0` | Сбросить настройки EEPROM к значениям по умолчанию |

**Особенность `0x30`:** в `main.py` одна и та же константа назначена `CMD_SLAVE_ADDR` и `CMD_GET_DATA`, поэтому две разные радиокнопки формируют один код команды. В прошивке `0x30` обрабатывается как **GET_DATA**; изменение адреса устройства через эту радиокнопку фактически не реализовано в протоколе текущей версии.

## Интерфейс Python-клиента

Окно содержит панель подключения, список операций и параметры отправляемого пакета. Для команды смены режима предусмотрен выбор **TEST / WORK**. Справа находятся вкладки **«Журнал»** (TX/RX-пакеты, ответы, ошибки) и **«График»** (измеренное выходное напряжение во времени). Доступны окна калибровки АЦП и VOUT.

Число пакета может автоматически увеличиваться при отправке. Флажок ожидания ACK присутствует в интерфейсе; фактическая работа ожидания зависит от того, с каким аргументом вызывается `send_packet()` — непосредственно пользовательская отправка и процедуры калибровки используют его по-разному.
